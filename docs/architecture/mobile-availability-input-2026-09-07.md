# 回答入力UIのモバイル操作設計（2026-09-07）

## 目的

回答者が7日分の候補を一覧で確認できる価値を維持しながら、390px前後の画面でセルを押しやすくし、表の操作がページの縦スクロールを妨げない状態にする。

## レイアウト仕様

- 640px未満の回答入力ページでは、入力表を画面幅へ均等配分する。
- `surface`、`AvailabilityForm`、入力表のモバイル用内側余白を重ねず、時刻列と7曜日を同じ表幅へ収める。
- 390px前後では各列を約48px、セル高を44px以上とし、7日表示を維持する。
- 320〜389pxでは列幅を画面幅に合わせて縮小するが、左右スクロールや3日表示への切り替えは行わない。
- 640px以上では既存のカード余白とデスクトップ向け表レイアウトを維持する。

## 操作仕様

- 曜日一括入力と日付別ヒートマップのセル操作領域は、原則44×44px以上とする。
- セルは`button`またはフォーカス可能な`role="button"`として、`aria-label`、`aria-pressed`、`aria-disabled`を付与する。
- Space / Enterでセルを切り替え、`:focus-visible`でフォーカス位置を明示する。
- viewportで`maximumScale`を制限せず、必要な場合にユーザーがズームできるようにする。
- 曜日・時間の候補が存在しないセルは操作対象から外し、`-`と「候補なし」で表示する。
- 表の外側はCSSの`touch-action`とブラウザ標準動作へ委ねる。回答入力ではポインター開始時の既定動作キャンセルとbody全体のスクロールロックを行わない。
- 640px未満では入力セルだけに`touch-action: none`を適用し、縦横ドラッグ中のセル選択を優先する。時刻列と表ラッパーは`pan-y`とし、左右スクロールを無効化したままページの縦スクロールへ連鎖させる。
- 既存のドラッグ選択は維持する。専用の移動量閾値や方向判定は追加せず、今後の実機テストで必要性が確認できた場合のみ検討する。
- 曜日一括入力と日付別ヒートマップは`table-layout: fixed`で8列を均等配分し、表内・ページ全体とも左右スクロール領域にしない。

## アカウント画面との整合

アカウント予定設定も7日単位の表と週ページングを使用しているため、回答入力の表も同じ日付範囲の考え方を維持する。回答入力ではセルの操作領域とフォーカス可能性を補強し、アカウント画面のネイティブボタン・アクセシブルネームのパターンへ近づける。

## 検証方針

- Jestで候補外セルのdisabled表示、キーボード操作、ヒートマップのbutton意味論、回答画面でのbodyロックなしを検証する。
- 390×844pxと320×700pxのブラウザで、表幅、縦スクロール、単セル選択、既存ドラッグ選択、横オーバーフローがないことを確認する。

## 受け入れ基準

- 640px未満では、回答入力の外側 `surface` とウィザード外枠をページ背景に統合し、外側の罫線・角丸・影・重複した内側余白を表示しない。
- DOMと視覚上の順序を「ステップ表示 → 回答ウィザード／現在ステップのタイトル → 説明 → 入力表 → 操作案内 → 次の操作」に揃える。現在ステップ名の見出しは1つだけにする。
- 曜日一括入力と日付別ヒートマップは、時刻列を含む7日表示を維持し、画面内幅へ均等配分する。表専用領域を含めて左右スクロールは許可しない。
- 時刻列は中立色と右境界で入力セルから分離し、選択イベントを持たせない。縦スクロールは時刻列・表外・ページで継続できる。
- 入力セルだけに `touch-action: none` を適用し、回答画面のドラッグ操作では `body` の `overflow`、`touch-action`、`overscroll-behavior` を変更しない。
- デスクトップ表示、週ページング、キーボード操作、候補外セルのdisabled表示を維持する。

## 実装メモ

- 回答入力ページの既存16px外側余白を残し、`availability-input-surface`、`availability-form-shell`、曜日一括入力カードを640px未満だけ透明化する。
- 表ラッパーを曜日表の`availability-weekly-matrix`とヒートマップの`availability-heatmap-scroller`として分離し、両方で`overflow-x: hidden`と`touch-action: pan-y`を適用する。表は8列を均等配分し、時刻列は`availability-time-column`で境界を表現する。
- `useSelectionDragController` は回答入力では `disableBodyScroll: false`、`preventDefaultEvents: false` を維持する。ポインターイベントは入力セルへだけ付与し、時刻列には付与しない。

## デザインQA追記（2026-09-07）

- 添付された現状画像は目標デザインではなく、外枠カードと内側カードの重なり、曜日一括入力見出しの重複、表前後の余白浪費を確認するBefore証拠として扱う。
- Afterはピクセル一致ではなく、文章で定義した受け入れ基準（モバイル限定のカード統合、見出し統合、7日表示、左右スクロール禁止、局所タッチ制御、縦スクロール維持）で判定する。
- 390×844のブラウザ検証では、カード境界の除去、見出し1つ、時刻列の非選択性、セル内キーボード／ドラッグ、body非ロック、console errorなしを確認した。詳細はルートの`design-qa.md`に記録する。
