# 既存回答編集メニューの再発防止設計（2026-08-13）

## 背景

イベント詳細の「既存の回答を編集」は、DaisyUIの`:focus-within`だけで開閉していました。デスクトップでは動作する一方、390px幅では右端揃えの固定幅メニューが画面左へはみ出し、操作に反応していないように見える状態でした。また、開閉状態を支援技術へ伝える属性と、再クリック・外側クリック・Escapeによる閉じ方がありませんでした。

## 実装方針

- 開閉状態はReactで明示的に管理し、DaisyUIのフォーカス有無を状態の唯一の根拠にしない。
- トリガーに`aria-haspopup="menu"`、`aria-expanded`、`aria-controls`を付ける。
- 再クリック、外側のポインター操作、フォーカス移動、Escapeで閉じられるようにする。
- Escapeで閉じた場合はトリガーへフォーカスを戻す。下矢印では開いて先頭項目へ移動し、メニュー内では上下矢印・Home・Endで項目間を移動する。
- 390px未満を含む狭い画面では左揃え、`sm`以上では従来の右揃えを維持する。
- メニュー幅と高さをビューポート以内へ制限する。

## 回帰検知

- Jestで開閉、外側操作、Escape、フォーカス復帰、下矢印、編集URLを検証する。
- Playwrightで実際のCSS適用後に`aria-expanded`と表示状態を検証する。
- Playwrightで390px幅へ切り替え、メニューの左右端がビューポート内に収まることを座標で検証する。
- 既存回答を選び、編集済みデータを保持した入力画面へ遷移できることを継続して検証する。

今後、同種のポップオーバーを追加する場合も、CSSの疑似クラスだけに開閉責務を持たせず、状態・終了操作・レスポンシブ境界・実ブラウザ座標を同じ基準で確認します。
